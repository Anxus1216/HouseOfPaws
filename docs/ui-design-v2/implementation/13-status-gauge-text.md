# 状态抽屉文字比例修复

## 原因和范围

`a31b69d` 引入的半圆进度条使用窗口逻辑像素：半径 18、线宽 5、数字中心位于圆心上方 5。百分比及状态名称却使用页面设计字号，再受页面整体缩放影响；短屏百分比约 11px，393 宽屏约 13.1px，430 宽屏约 14.3px，文字变大后挤向固定尺寸的弧线。此前抽屉高度适配的回退不涉及该字号公式。

按确认方案，以原短屏效果为基准，百分比和名称均固定为 11 窗口逻辑像素。仅调整这两处绘制，不修改全局文字函数。保留抽屉 52px 宽、268px 高度上限、四行排版、半圆弧线及文字中心位置。

## 验证

- `npm test`：152/152 通过。新增参数回归覆盖 320×568、393×852、430×932，DPR 1/3，以及 0%、45%、80%、99%、100%；核对文字、半径、线宽、相对位置、状态名称和抽屉尺寸。
- 原半圆测试改为拦截最终 `text` 绘制，继续检查四项状态及进度。
- 独立审查：相关测试 15/15 通过，`git diff --check` 通过，未发现问题。
- 微信开发者工具 Stable 2.02.2608080，通过工具文档 URL 确认项目路径为当前工作区，编译后检查 iPhone 5（320×568，100%）和 iPhone 15 Pro Max（430×932，100%；85% 补充完整布局）。
- 实际打开状态抽屉，查看约 44–45%、80%、60%、100% 与弧线的间隙；两机型均通过任务导航返回小屋，抽屉保持展开且显示正常。机型重启后抽屉收起，重新打开正常。
- 机型切换出现一次模拟器长时间无响应提示，关闭提示并重新编译后沿同一路径复测正常。没有清除缓存或覆盖存档，也未领取奖励或执行照料，爪爪币保持 60。

## 限制

模拟器检查不等同真机验收。0% 和 99% 由参数测试覆盖，未通过修改存档构造实际画面；不同真机系统字体的字形边缘仍需真机验证。
