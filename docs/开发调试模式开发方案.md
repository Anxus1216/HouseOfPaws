# 爪爪小屋｜开发调试模式软件开发方案

状态：已实施并完成模拟器回归　｜　版本：v1.1　｜　日期：2026-10-18
需求依据：[开发调试模式 PRD](./开发调试模式PRD.md)

## 1. 目标与完成定义

本方案在现有微信小游戏 Canvas 架构中增加开发调试编辑器。开发人员通过本地配置开启入口，直接设置当前陪伴萌宠的数值、爪爪币和今日任务状态。关闭配置时没有入口且调试写入被拒绝；开启后编辑结果通过现有存档键持久化。

完成条件：PRD 第 7 节场景通过自动测试与微信开发者工具模拟器回归；发布配置经脚本检查为关闭；不改变正常照料、每日结算和奖励流程。需覆盖旧存档的破坏性调试场景由自动测试验证，模拟器保留现有存档。

## 2. 现状与约束

| 位置 | 现状 | 对开发的影响 |
| --- | --- | --- |
| `js/model.js` | 本地存档版本 3，键为 `paw_house_save_v1`；宠物数值、今日成长、任务进度与领奖状态均已定义 | 复用现有字段，不新增调试专用存档字段；校验范围需与存档读取保持一致 |
| `js/main.js` | 统一处理触摸、时间结算、30 秒周期存档、设置弹层及小游戏暂停 | 调试操作要有独立入口和提交路径；现有 `save()` 会先结算时间并吞掉存储异常，不适合作为原子提交的唯一接口 |
| `js/scene.js` | 所有页面与设置由 Canvas 绘制；点击区域保存在 `buttons`；逻辑宽 390，最低适配高度约 680 | 调试编辑器也需自己处理绘制、滚动、触摸遮挡和键盘区域 |
| 构建 | `game.js` 直接加载 ES 模块，仓库没有打包器 | 不能把开发者工具的 `project.private.config.json` 当作游戏运行时配置，也不能静态导入一个可能不存在的本地文件 |
| 测试 | `tests/model.test.mjs` 检查规则；`tests/game-smoke.test.mjs` 用微信 API 桩检查主流程和页面边界 | 新增纯逻辑测试及入口、输入、保存的交互测试；复用现有测试命令 |

## 3. 技术设计

### 3.1 配置接入与发布保护

采用**可选开发配置源 + 始终存在的运行时模块**，避免缺文件导致小游戏启动失败。

1. 仓库提交 `config/debug.json`，内容为 `{ "debug": { "enable": true } }`，并提交对应的开启版运行时模块；开发人员直接编译即可进入调试模式，无需复制或改名文件。配置文件列入小游戏打包忽略列表，不用于游戏内存储。
2. `scripts/prepare-debug-config.mjs` 读取配置文件，仅对布尔值 `true` 输出开启；文件缺失、字段缺失、`false`、其他类型或解析失败均输出关闭并给出可读提示。脚本生成 `js/debug-config.generated.js`，只导出布尔常量。修改配置后运行脚本并重新编译。
3. `js/main.js` 读取生成的常量并传递给界面；调试提交模块也在写入前检查同一常量。隐藏按钮和拒绝写入是两道独立检查。配置启动时确定，修改源文件后必须重新运行准备脚本并编译/重启。
4. 新增发布检查脚本：检查生成模块仍为关闭，校验发布包中不包含本地配置源；发布构建先强制生成关闭模块，再执行检查。检查失败即停止发布。调试包在设置和编辑器中持续显示「开发调试已开启」。

这个开关只限制正常构建中是否出现调试能力；客户端代码不能提供真正的身份鉴权。开发版默认开启，因此发布前必须运行关闭检查并重新编译。

### 3.2 数据模型与字段校验

新建 `js/debug-editor.js`，集中实现 `createDraft(state, now)`、`validateDraft(draft, state, now)` 和 `applyDraft(state, draft, now)` 等纯逻辑。草稿保存输入字符串，直到提交前才转换为数值；这样空字符串不会被 `Number('')` 误判为 0。

| 数据组 | 字段 | 校验与联动 |
| --- | --- | --- |
| 当前宠物 | `hunger`、`clean`、`happy`、`energy` | 有限数值 0–100，最多两位小数；草稿显示至多两位，未编辑字段保留存档原始精度 |
| 当前宠物 | `level`、`xp` | 整数；等级 1–99；1–98 级经验为 0 至 `level × 40 - 1`，99 级经验只能为 0；两字段作为一组校验 |
| 当前宠物 | `actions`、`dailyGrowth.earned` | 非负整数，分别上限 999999 和 100；不联动 `totalActions`、历史经验或奖励 |
| 全局 | `coins` | 整数 0–999999；直接设置余额 |
| 今日任务 | 每项 `progress`、`claimed` | 进度为 0 至当前 `TASKS.target` 的整数；已领奖必须已达目标；直接改已领奖不发币 |

输入采用严格十进制格式：拒绝空白、负数、指数写法、非有限数、整数项的小数、浮点项超过两位小数、越界值；不静默截断。错误按字段返回，以便界面定位。未领养时草稿不含宠物编辑部分，但币和任务仍可修改。宠物 ID、任务 ID 来自当前状态和 `TASKS`，不能由输入任意指定。

今日任务和成长各记录一个日期标记。草稿创建时记录现有规则判定的有效日期；提交前在候选状态上运行日期更新，再比较标记。若日期变了，拒绝本次提交、更新编辑器数据并提示重新确认。时钟回拨时保留较新的已有日期，和当前模型行为一致。

### 3.3 原子提交与时间顺序

提交顺序固定，避免调试数值刚保存就被旧时间戳再次结算：

```text
确认开关与当前宠物 ID
→ 取同一个 now，克隆当前业务状态
→ 在候选状态执行 settleTime、ensureTasks、成长日期更新
→ 检查草稿日期及全部字段
→ 把合法值写入候选状态，保持 settleTime 计算后的 lastSeen（时钟回拨时可晚于 now）
→ 一次调用 wx.setStorageSync(STORAGE_KEY, candidate)
→ 存储成功后替换内存状态、关闭编辑器并重绘
```

存储失败时不替换内存状态，不关闭编辑器，保留草稿并提示重试。正常时间结算可以继续发生，但无效输入和存储失败不能造成部分调试字段写入。提交不调用 `care`、`addXp`、`recordTask`、`claimTask`、`daily` 或 `miniReward`，因此不产生附带奖励、音效或任务事件。关闭配置时提交函数直接拒绝，即使收到伪造的点击 ID 也不会写入。

在 `js/main.js` 中让普通存档和调试提交共享底层可观察的存储结果，避免沿用当前 `save()` 捕获异常后仅显示提示、调用者仍误以为保存成功的行为。若只为调试路径新增存储函数，不能改变普通玩法的既有结算时机。

### 3.4 Canvas 编辑器与输入

- 在设置弹层加入「调试模式」入口；点击后关闭设置、打开独立的全屏编辑层。绘制时以调试层覆盖底层页面，并清空底层点击区域，只登记编辑器按钮，防止穿透点击。
- 顶部固定显示「开发调试已开启」、当前宠物名称/ID、任务日期与成长日期；中间按状态、成长与等级、资源、今日任务分组滚动；底部固定「取消」「保存」。无宠物时显示提示并隐藏宠物字段。
- 数值字段显示当前原始值，点击字段打开 Canvas 数字键盘。它支持替换、逐位删除、清空、小数和取消，输入只更新草稿，不直接修改游戏状态；短屏中与固定操作栏分开绘制。
- 布尔领奖状态用明确的「未领奖 / 已领奖」切换；进度为 0/1 时可用单击选择，同时保留未来任务目标大于 1 时的数字编辑能力。编辑器显示字段错误文本；保存时滚动到首个错误。
- 滚动位置按内容高度限幅，命中区域随滚动同步，内容在固定底栏上方裁剪。键盘打开后根据可用高度调整可视区，避免编辑中的字段和保存操作被遮挡；按 390×680、390×844 两个逻辑尺寸检查。
- 若从进行中的小游戏打开设置，沿用当前暂停机制。编辑器关闭后回到原页及暂停状态，不偷偷恢复计时。关闭或取消有未保存改动时二次确认；切后台时保留草稿，不自动提交。

### 3.5 文件级改动

| 文件 | 计划改动 |
| --- | --- |
| `config/debug.json` | 提交默认开启的开发配置，开发人员可直接编译 |
| `project.config.json` | 打包时排除开发配置源 |
| `scripts/prepare-debug-config.mjs`、发布检查脚本 | 生成运行时开关并阻止调试开启的发布包 |
| `js/debug-config.generated.js` | 提交默认开启的开发版本；发布前由检查脚本改为关闭 |
| `js/debug-editor.js` | 草稿、严格校验、日期检查、候选状态生成；保持独立于 Canvas |
| `js/main.js` | 入口状态、触摸路由、键盘生命周期、可观察的持久化提交、暂停与重绘 |
| `js/scene.js` | 设置按钮、编辑器绘制、滚动和命中区域 |
| `tests/debug-editor.test.mjs`、`tests/game-smoke.test.mjs` | 规则边界、保存副作用、配置开关、主路径与布局边界 |
| `README.md` 或开发文档 | 启用步骤、重新生成与发布前关闭检查 |

原则上不修改存档版本；若实施中确实需要新持久化字段，先设计 v4 迁移及旧档测试，再进入界面开发。

## 4. 实施顺序与阶段验收

| 阶段 | 工作 | 阶段通过条件 |
| --- | --- | --- |
| 1. 输入与配置验证 | 在微信开发者工具确认目标项目；实现开发版默认开启、配置生成和发布检查 | 直接编译可开启；缺失或无效配置经准备脚本生成关闭；发布检查强制关闭 |
| 2. 规则与提交 | 实现草稿、严格校验、日期标记、候选状态和原子写入 | 自动测试覆盖字段边界、等级/经验、任务领奖、跨日、写入失败和关闭态拒绝 |
| 3. 页面与交互 | 设置入口、编辑器、键盘、滚动、取消确认、错误提示、小游戏暂停 | 自动交互测试可走完整路径；短屏和高屏的按钮边界、输入及遮挡检查通过 |
| 4. 集成回归 | 用隔离测试存档在模拟器测试新手无宠物、已领养、任务、小游戏、重启和关闭配置 | PRD 验收场景通过；正常玩法测试通过；发布配置检查通过 |

每阶段完成后再合并下一阶段。功能代码、对应测试和相关文档纳入同一个 `feature: ` 提交；若回归发现独立旧问题，另用 `bugfix: ` 提交。提交前检查暂存区，仅纳入本需求文件，不带入现有 `project.private.config.json` 和宠物素材目录的未归属改动。

## 5. 测试与模拟器回归

自动测试命令沿用 `node --experimental-default-type=module --test tests/*.test.mjs`，并补充以下重点：

- 配置矩阵：缺文件、缺字段、`false`、字符串 `"true"`、解析错误和布尔 `true`；关闭状态既无按钮也无法调用调试提交。
- 字段矩阵：上下限、空值、无穷大、非法格式、小数精度、99 级经验、已领奖但进度不足；一个字段错误时没有部分写入。
- 行为矩阵：修改数值不增加币、经验、任务或动作次数；设任务待领奖后仅正常领取一次；存储抛错时仍保留草稿及原内存值；重启后合法值保留。
- 时间矩阵：打开编辑器后自然结算、跨日、时钟回拨、后台返回；保存后的 `lastSeen` 与显示一致。
- 页面矩阵：390×680 和 390×844 的滚动区域、固定底栏、点击命中、键盘遮挡、设置/小游戏暂停层级。

模拟器执行顺序：先运行相关自动化测试；确认微信开发者工具窗口打开的确为当前工作区；重新生成配置并编译最新代码；观察当前画面后再点击「设置 → 调试模式」，逐屏重新观察并测试输入、保存、取消、错误提示、任务领奖与金币反馈；在关闭配置后重编译确认入口消失。分别检查短屏与较高屏。使用独立测试实例或隔离存档做破坏性数据场景，保留用户现有模拟器存档和项目配置；若必须覆盖现有存档，先确认影响。

若模拟器无法提供所需屏幕尺寸，补充布局边界测试并记录限制。模拟器结果仅作为模拟器回归，真机仍需检查虚拟键盘、安全区、触摸精度与存档行为。

## 6. 风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 调试开启的生成模块误进发布包 | 发布前强制生成关闭、脚本检查、重新编译并人工核对设置入口 |
| 修改等级但经验与之冲突 | 同组严格校验，禁止自动升级或偷偷清零 |
| 当前数值含时间结算的小数，界面显示后再保存发生精度漂移 | 草稿显示至多两位小数；未编辑字段直接保留原值；仅解析实际修改的字段 |
| 编辑期间跨日或切后台 | 日期标记失效即拒绝提交并刷新；暂停小游戏，保留草稿 |
| Canvas 键盘与软键盘遮挡、输入事件不一致 | 先做目标环境验证；输入适配层与业务校验分离，必要时改用 Canvas 数字键盘 |
| 写入失败导致内存与本地存档不一致 | 候选状态先写存储，成功后才替换内存；界面显示失败并允许重试 |

## 7. 待评审的具体决策

本期已按 PRD 实现当前陪伴萌宠的数字字段、爪爪币和今日任务进度与领奖状态，直接改领奖状态不会补发奖励。开发版默认开启，状态数值最多支持两位小数。为保证小数输入、清空和短屏操作一致，采用 Canvas 数字键盘。自动测试 45 项通过；微信开发者工具的 iPhone 5（320×568）和 iPhone 15 Pro Max（430×932）模拟器已检查设置入口、编辑器、字段显示和两位小数输入限制。真机触摸与存档行为仍需真机验收。
