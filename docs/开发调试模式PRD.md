# 爪爪小屋｜开发调试模式 PRD

状态：已实施　｜　版本：v1.0　｜　日期：2026-10-18

## 1. 背景与目标

游戏数值会随时间、照料、互动、小游戏和每日任务变化。开发人员目前只能反复执行玩法或直接改本地存档，难以稳定复现低精力、满级、成长额度用尽、任务待领奖等情境。

本需求提供由开发配置开启的游戏内调试入口，让开发人员在运行中查看和修改**当前陪伴萌宠**及相关全局数据，并将结果保存到当前设备的本地存档。普通配置下不显示入口，也不接受调试编辑操作。

### 成功标准

- 开发人员能在设置中进入调试模式，修改目标数值并立即看到游戏页面更新；重启后修改仍在。
- 缺少 `debug.enable` 或其值为 `false` 时，设置中没有调试入口，触摸事件也无法进入编辑器或调用调试写入逻辑。
- 输入无效时提示具体字段与合法范围，不产生部分写入或损坏存档。
- 调试编辑本身不触发照料、升级、任务领奖、每日礼物或小游戏奖励。

## 2. 使用者与范围

使用者为可修改项目开发配置并运行开发/测试构建的开发人员和测试人员。配置由项目维护者管理；游戏内不提供打开调试模式的开关。

| 优先级 | 范围 | 本期要求 |
| --- | --- | --- |
| P0 | 调试配置与入口 | 仅当配置项 `debug.enable === true` 时，在现有「小屋设置」弹层显示「调试模式」按钮；缺字段、`false` 或其他值均视为关闭 |
| P0 | 当前陪伴萌宠 | 编辑饱腹 `hunger`、清洁 `clean`、快乐 `happy`、精力 `energy`、等级 `level`、经验 `xp`、照料次数 `actions`、今日已获成长 `dailyGrowth.earned` |
| P0 | 全局数据 | 编辑爪爪币 `coins`；编辑今日三个任务 `care`、`interact`、`game` 的完成进度 `tasks.progress` 和领奖状态 `tasks.claimed` |
| P0 | 保存与反馈 | 校验后一次性应用并写入现有本地存档，关闭编辑器后刷新小屋、任务、金币和成长显示；支持取消放弃修改 |

不在本期：修改其他未陪伴萌宠、领养状态、宠物名称、引导进度、音效、每日礼物领取日期、系统时钟、任务定义和奖励额度；批量预设、远程调试、跨设备同步和生产环境用户授权。当前存档里的 `totalActions` 是全局累计字段，本期不开放编辑。

## 3. 配置与可见性

1. 开发侧提供一个**随构建确定**的调试配置文件，配置对象采用 `debug.enable` 字段；示例为 `{ "debug": { "enable": true } }`。正式构建的默认值为 `false`。文件路径、打包读取方式由技术设计确定，并确保游戏运行时代码实际获得该值；现有 `project.private.config.json` 属于开发者工具配置，不能直接假定游戏可读取。配置必须可由开发人员修改，不能靠玩家在游戏内操作开启。
2. 启动时读取配置；仅布尔值 `true` 开启。缺少配置文件、缺少 `debug`/`enable`、显式 `false`、字符串 `"true"`、读取失败都按关闭处理。
3. 开启时，现有设置弹层在音效区域下显示「调试模式」按钮。点击进入调试编辑器。关闭时不绘制按钮；事件处理和数据写入也必须再次检查开关，不能只依赖隐藏 UI。
4. 调试配置不写入玩家存档。将配置从开启改为关闭并重新构建/启动后，入口消失；此前保存的数值仍按普通存档继续运行，不自动回滚。
5. 开发/测试构建应明确标识调试状态；发布构建需检查配置为关闭。配置开关控制的是**构建中的调试能力**，不能当作客户端内的身份认证。

## 4. 操作流程与界面

1. 开发人员打开设置，点击「调试模式」。若尚未领养宠物，编辑器展示提示「先领养一只萌宠」，宠物字段不可编辑；爪爪币和今日任务仍可编辑。
2. 编辑器顶部显示当前陪伴萌宠名称、ID 和正在使用的任务/成长日期，便于确认修改对象。编辑器打开后目标宠物固定；在外部切换陪伴萌宠后再次打开，显示新宠物。
3. 按「萌宠状态」「成长与等级」「资源」「今日任务」分组显示当前值和输入控件。任务分别显示目标、当前进度和「已领奖」状态。短屏可滚动，保存/取消/关闭操作始终可到达；输入数值时使用数字键盘并允许清空重填。
4. 点击「保存」时先结算截至保存时刻的正常时间变化，再校验并应用这次编辑；成功后写入本地存档，显示「调试数据已保存」，退出编辑器并刷新相关页面。之后的自然变化从保存时刻继续。
5. 点击「取消」或关闭编辑器，丢弃尚未保存的输入。若有未保存修改，需提示确认放弃；保存失败时保留输入和编辑器，显示失败原因。
6. 从小游戏进行中打开设置时沿用现有暂停逻辑；编辑器打开期间小游戏保持暂停，返回后由开发人员按现有方式继续或结束。

## 5. 字段规则

| 字段 | 可输入值 | 规则 |
| --- | --- | --- |
| 饱腹、清洁、快乐、精力 | 0–100 的有限数值 | 允许小数以保留时间结算结果；显示和保存精度应一致，不得因界面取整意外改值 |
| 等级 `level` | 1–99 的整数 | 直接设为目标等级，不自动补发升级奖励 |
| 经验 `xp` | 非负整数；等级 1–98 时小于 `level × 40`，等级 99 时只能为 0 | 与所设等级同时校验；不因调试输入自动升级或换算经验 |
| 照料次数 `actions` | 0–999999 的整数 | 仅调整当前宠物的记录，不联动全局 `totalActions` 或今日任务 |
| 今日已获成长 `dailyGrowth.earned` | 0–100 的整数 | 修改当前陪伴萌宠当日额度占用，不追溯或扣回经验、等级和奖励；保存时关联当前有效成长日期 |
| 爪爪币 `coins` | 0–999999 的整数 | 直接设置余额，不触发货币获得事件 |
| 每项任务进度 | 0 至该任务 `target` 的整数；当前三个任务目标均为 1 | 修改进度不触发任务行为、音效或奖励 |
| 每项任务已领奖 `claimed` | 是/否 | `claimed=true` 时进度必须达到目标；直接设为已领奖不补发爪爪币；改为未领奖后，达到目标的任务可按正常流程再领取 |

所有必填字段须拒绝空值、非数字、`NaN`、无穷大、超范围值和不符合整数要求的值。对无效输入不静默截断或钳制。一次保存作为单个事务处理：任一字段无效则全部不写入，并在对应字段展示原因。

「今日」沿用现有本地日期和时钟回拨规则：任务进度关联 `tasks.date`，成长额度关联该宠物的 `dailyGrowth.date`。编辑器显示正在编辑的有效日期，不提供日期输入。若编辑期间跨日，保存前刷新日期相关数据并提示重新确认，避免把前一日的进度写入新的一日。

## 6. 与现有规则的关系

- 调试保存是**直接设置最终值**。它不调用照料、互动、任务记录、任务领奖或小游戏奖励流程，也不产生升级币；正常玩家操作仍按现有规则结算。
- 更新当前宠物四项状态、等级、经验和今日成长后，小屋状态条、等级/经验展示、照料可执行条件、今日成长展示立即使用新值；任务页和顶部金币同步更新。
- 保存在现有 `paw_house_save_v1` 本地键下，并复用现有存档校验与迁移约束；不把调试开关或编辑器临时状态写入存档。若实现需要调整存档结构，应提供兼容迁移。
- 关闭调试入口不改变正常的离线结算、每日重置、金币上限与满级规则。自然结算可能在保存后继续改变四项状态，这是预期行为。

## 7. 验收场景

| 场景 | 预期结果 |
| --- | --- |
| 配置为 `true` / `false` / 缺字段 / 无效值 | 仅 `true` 时在设置中看到并能打开调试模式；其余情况无法进入或写入 |
| 把精力设为 15、快乐设为 100、今日成长设为 100 | 首页立即显示新状态；照料及成长额度按原规则生效；后续时间变化正常继续 |
| 把等级设为 99、经验设为 0 | 显示满级；调试保存不发升级币，后续照料不再获得经验 |
| 把爪爪币设为 0 或 999999 | 顶部余额立即更新；正常消费/奖励仍遵守余额上下限 |
| 设置任务进度达标、未领奖 | 任务页显示「领取奖励」；点击后只领取一次，金币按正常任务奖励增加 |
| 直接把任务设为已领奖 | 任务显示已领取；保存动作本身不增加金币 |
| 输入越界、非数字、冲突的等级/经验或已领奖/进度组合 | 对应字段报错；调试字段不发生部分写入，正常时间结算不受影响 |
| 取消编辑、重启游戏、关闭调试配置再启动 | 取消不写入；成功保存的值重启后保留；关闭配置后只隐藏调试能力，不回滚数值 |
| 编辑器打开期间跨日或切后台再返回 | 日期相关字段不会写错日期；小游戏保持暂停；无重复奖励 |
| 无宠物、矮屏和常见竖屏比例 | 无宠物时有明确提示；字段及保存/取消按钮可读可操作，不与系统安全区冲突 |

验收以规则测试和微信开发者工具交互检查为基础；发布前仍按项目现有验收流程做真机比例与触摸检查。
