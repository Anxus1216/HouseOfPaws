# 爪爪小屋｜首个可玩版本开发方案

状态：方案基线（2026-10-14）。载体是**微信小游戏**；本轮目标是做出能完整体验、可真机验证的萌宠养成版本。上线审核、商业化和社交传播不在本轮承诺范围内。

## 1. 项目现状与目标

现有代码已经提供：首次领养、三只宠物、四项状态、喂食/清洁/玩耍/休息、等级经验、爪爪币、每日礼物、离线状态结算、接星星小游戏和本地存档。当前问题是角色外形主要共用一个轮廓，行为缺少视觉反馈，玩家除数值升级和解锁宠物外没有清晰的短期目标；存档和小游戏也仍需真机验收。

本轮的玩家体验目标是：首次进入 30 秒内认识并领养一只宠物；3 分钟内完成一次照料、看到状态及表情变化、玩一局小游戏并获得奖励；次日回来有明确可领取、可继续完成的目标。基调是温柔、轻松、无惩罚；低状态只提示照顾，不出现死亡或永久失去宠物。

## 2. 开发必需流程与交付关口

| 阶段 | 要解决的问题 | 本轮交付物与通过条件 |
| --- | --- | --- |
| 需求锁定 | 谁玩、玩什么、什么算完成 | 本文的核心循环、范围和验收标准确认；任何新增玩法先评估工期及影响 |
| 体验设计 | 玩家从进入到次日回访怎样行动 | 首页、领养、图鉴、任务、小游戏的流程和状态稿；可逐屏说明按钮结果 |
| 美术预制作 | 角色与界面是否统一、能否批量产出 | 角色设定表、色板、线条/表情/动作规范；先做一只角色完整样张验证 |
| 技术实现 | 规则、表现、存档能否稳定协同 | 模型规则、Canvas 场景、触摸反馈、本地存档迁移；主要流程可运行 |
| 验证调优 | 真机能否读清、点中、流畅运行 | 自动规则测试、开发者工具检查、至少两种屏幕比例真机体验记录及修复 |
| 发布准备 | 能否作为微信小游戏提交 | 图标/启动素材、隐私与权限核对、版本号、体验版回归和审核资料；另行决定提交时间 |

每阶段先产出可评审的结果，再进入下一阶段。美术样张与任务/存档规则应先于大量页面制作，避免整套资源返工。

## 3. 核心玩法与本轮功能

**核心循环：**打开小屋 → 看宠物心情与需求 → 选择照料动作 → 状态、表情与成长获得即时反馈 → 完成每日小目标/玩小游戏 → 获得爪爪币 → 领养新伙伴或继续培养 → 次日回访。

| 优先级 | 功能 | 本轮具体要求 | 验收方式 |
| --- | --- | --- | --- |
| P0 | 首次领养与引导 | 首次进入突出免费领养奶糖；领养后用 2–3 个可跳过的步骤说明状态、照料和游戏入口 | 新玩家不看说明也能在 30 秒内完成领养；重复进入不重播强制引导 |
| P0 | 照料反馈 | 保留四项状态及四个动作；每次操作显示状态变化、对应表情/短动作与文案；金币不足和精力不足有明确提示 | 点击后数值、金币、存档同步；连续快速点击不会重复结算或出现负值 |
| P0 | 成长与日常目标 | 保留等级经验和每日礼物；加入每日 3 个简单任务（照料、互动、完成小游戏），完成后领取一次奖励 | 跨本地日期重置任务；当日重复领取无效；重新打开后进度仍在 |
| P0 | 接星星小游戏 | 保留 20 秒玩法；补开始说明、倒计时、接中反馈、结果页和重新开始入口 | 一局只结算一次；离开或切后台时暂停，恢复后不额外消耗时间 |
| P0 | 存档与兼容 | 沿用现有存档数据并做版本迁移；保存宠物、货币、任务和引导进度；处理异常数据 | 旧存档可打开；前后台切换和重启后关键进度一致 |
| P0 | 适配与可读性 | 覆盖常见竖屏比例，安全区域内呈现主要按钮；文字、颜色和触摸区域可读可点 | 开发者工具及至少两种真机比例完成完整流程，无遮挡和误触 |
| P1 | 角色表现 | 三只宠物各有独立轮廓、耳朵/尾巴、花纹和专属小动作；支持待机、开心、困倦、需要照顾 | 缩到图鉴尺寸仍能区分；状态变化在首页可感知 |
| P1 | 轻量音效与开关 | 领养、照料、接星星、升级提供短音效；设置入口可静音，默认尊重设备静音 | 开关重启后保留；音效不盖过系统声音 |

**明确留到后续：**联网账号与跨设备同步、好友互访、排行榜、装扮商城、付费道具、广告、复杂繁殖与战斗。这些会引入服务端、内容产能或合规工作，不纳入首个可玩版本。

## 4. 美术方向

主题为**“午后甜点小屋”**：像纸张与奶油陶器组成的温暖室内，轻柔但要有清晰的操作层级。主背景用暖奶白 `#FFF7EF`，大面积卡片用 `#FFFDF9`，行动主色用珊瑚橘 `#E98778`，文字深棕 `#554139`，辅助色为薄荷绿 `#A9C8AE`、浅粉 `#F5B8AD`、星光金 `#EFC77E`。避免整屏同样浅的颜色：关键按钮与正文需提高对比。

造型规则：头部占角色总高约 45%，身体为柔软梨形；外轮廓圆润，尖角只用于耳尖和星星；采用少量成块阴影，不画写实毛发。角色外轮廓和五官用统一深棕色，线宽随尺寸缩放。表情每只至少有普通、开心、困倦、委屈四组。动效以呼吸、眨眼、耳朵/尾巴摆动为主，动作时长短，避免频繁闪烁。

界面规则：顶部只放标题、金币和当日入口；中央始终突出当前宠物；状态区只显示四个一致的短标签；四个照料按钮同时可见，图标不能单独承担语义，必须带文字。小游戏与日常目标可复用卡片、按钮、反馈气泡。先做 390×844 逻辑尺寸，再对较矮屏幕检查内容压缩和安全区。

素材策略：先画奶糖的待机、四表情和四动作，放进首页真机验证尺寸；通过后按同一规格制作糯米、团团。资产可以继续使用 Canvas 绘制，也可采用透明 PNG 精灵；最终选型以真机清晰度、包体和制作效率决定。导出时保留源文件，命名为 `pet_<id>_<state>_<frame>`，图片采用透明背景并记录锚点，避免不同角色跳位。

## 5. 三只萌宠形象设定

| 角色 | 外形识别 | 性格与动作 | 配色与专属物件 |
| --- | --- | --- | --- |
| 奶糖 · 奶油小猫 | 奶油色圆脸、短三角耳、额前一撮弯曲奶油纹、细长尾巴；脸颊有两点焦糖雀斑 | 慢热、喜欢晒太阳；被摸时眯眼蹭手，开心时尾巴轻卷 | 奶油 `#F5CDA5`、焦糖 `#D78B78`；珊瑚色铃铛围巾 |
| 糯米 · 垂耳小兔 | 两只向外下垂的长耳、云朵形刘海、短绒尾；轮廓比奶糖更纵向 | 细心、爱收藏云朵；开心时耳朵弹起，困倦时抱着小云朵 | 米白 `#E8D9C9`、莓粉 `#D9A7B0`；薄荷色领巾 |
| 团团 · 小柴犬 | 宽脸、立耳、眉点、白色口鼻区与卷尾；轮廓最结实 | 热情、爱奔跑；玩耍时前爪踏步，委屈时耳朵微垂 | 杏橘 `#DFA777`、红棕 `#B6785C`；星星挂牌 |

三只角色共用“圆润、短手脚、深棕五官”的家族语言，但**脸形、耳形、尾形、额头特征**必须各不相同。角色不能只靠颜色辨别，以保证小尺寸图鉴仍清楚。

## 6. 页面与数据约定

首页：宠物和房间、状态、成长条、四个照料动作、当日目标入口。图鉴：拥有状态、领养价格、切换陪伴对象。任务页：三个任务的进度与可领奖状态。游戏页：玩法说明、倒计时、得分、暂停/结果与再玩。设置页可先做轻量弹层，只含音效开关和存档说明。

任务采用本地日期键，进度来源于真实行为事件，不因反复打开页面增加。任务奖励和每日礼物分别记领取状态。存档增加明确版本字段，迁移时补默认值，不重置旧宠物和金币。所有时间结算需处理手机时钟回拨、切后台和超长离线；离线衰减维持现有 24 小时上限。

## 7. 实施顺序与完成定义

1. 确认本方案，画关键页面线框及奶糖完整样张；按真机实际尺寸验证角色和按钮。
2. 实现任务规则、引导进度、存档迁移与小游戏暂停；先用规则测试锁定奖励边界。
3. 完成三个角色的差异化表现、照料反馈、界面视觉统一和音效开关。
4. 走一遍首次进入、次日回访、金币不足、低精力、满级、旧存档、前后台切换的流程；修复真机问题。
5. 准备体验版素材和审核信息，决定是否提交发布。

本轮“完成”指 P0 全部通过，P1 角色表现达到三只可区分且四种情绪可见；小游戏、任务与存档通过自动测试和真机回归。音效若受素材制作影响可单独延期，但必须在体验版记录。当前仓库已有未提交改动，实施时应在现有工作基础上继续，先确认改动归属并避免覆盖。
